Fix soundness bug and use-after-free in mem_facet propagation/split

Soundness bug: mem_propagation::propagate previously called seq::accepts
on the un-derived view state whenever a membership's string still had a
leading variable ('bad' branch), which only tests nullability of the
*original* regex and says nothing about the variable-containing string.
This unsoundly discharged memberships like x ++ "ab" ++ x in (aba)*
as satisfied merely because (aba)* is nullable. Fixed to defer to
l_undef (split plugins) unless the string is fully concrete.

Use-after-free: mem_monadic_split::iterator previously constructed its
seq_monadic engine against the shared search-tree trail_stack.
seq_monadic::add() pushes undo-trail entries referencing its own
internal state onto that trail; when the plugin declined without
committing, extend_node()'s scoped_push would immediately pop that
trail scope, running those entries' undo() against an already-destroyed
seq_monadic/iterator - a use-after-free crash. Fixed by giving each
iterator its own private trail_stack, decoupled from the shared
search-tree trail and torn down together with the seq_monadic engine
that uses it.

Verified via C:\bench\inputs\regexes 1476-file sweep with
smt.string_solver=nseq -T:5: crashes 144->0 (real access violations),
wrong-answer count 249->3.
